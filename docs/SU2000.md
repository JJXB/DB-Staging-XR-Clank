## 1. The 30-second version

1. The SU-2000 (aka 2000SU, Virtuality "SU" standing / CyberBase console
   family, manual dated March 1994) is a **2-player 486-DOS arcade VR pod**
   that sold for **$100K in 1995**: two standing platforms (visette HMD,
   joystick, handbar emitter, card reader, speaker/buttons, Format-D box,
   12/5/-5V PSU each) driven by one rackmount electronics box under
   platform #1 holding a **14-slot ISA backplane** (§2).
2. Game compute is split: **486 runs DOS 6.22 + game logic**, **twin MC88110
   RISC CPUs per PIX 1000 card do 3D** (one card per player), **N80C198
   MCS-96 MCU on FORMAT C does system control**, **TMS320C31 DSP on each
   Polhemus tracker card does tracking**, **Ensoniq OTTO/ODIE does audio**.
3. Video path: SVGA (menus/ETS) → FORMAT C twin RGBS→composite converters →
   VID 1000 scan/format stage → Visette 2000 HMD. PIX 1000 is the 3D frame
   source. Broadcast/OSD text protocol sits on **port `0x320`** (big-endian
   16-bit words, `001F/001C/0022` verbs). RGBS-level video is exposed at
   FORMAT C outputs (a second unit taps it for external monitors, §13).
4. Audio path is an **Ensoniq Soundscape S-2000 (possibly S-1000) island on
   FORMAT C** (JP1 base `320/330/340/350`, JP5 IRQ `10/11/12/15`,
   MITSUMI CD-ROM IF, 4 MB SIMM sample RAM, 128 kbit DRAM, OTTO = ES5506,
   ODIE = ES5706) plus FORMAT-C volume-register block at **IO+0…7**.
   Sample RAM must sit in the *front* slot or games crash on startup (§13).
5. Control path is FORMAT C's **2 KB ISA memory window** (WFC067A vs WFC067B
   maps; window e.g. `CC000…` / `D0000…` / `E0000…`, version byte
   `0x21`=2.10 / `0x30`=3.00, status `0x82`, sync `A5/5A` toggle,
   brightness/joystick/glove/switch/console/security/backlight bytes,
   command block at `0x400`). The `config.vpc` contract is verbatim in §10.
6. Tracker is a stock **Polhemus InsideTrak ISA board (FasTRAK reduced to 2
   sensors)** — **two of them in a 2-player unit** (each with a 3A0417
   adapter box): S1 base `0x270/0x278` (+4/+8/+10/+20/+40/+80/+100/+200
   adders), JP8 IRQ `3/4/5/6/7/9/10/11/12/14/15`, firmware
   `VER.151.01/.02/.03/.07`.
7. Link is a cheap **8390-class ISA NIC (COMPEX ReadyLINK ENET16/V on the
   documented unit, 10Base-2 generic on the second)**: 16 KB SRAM, mem
   `C0000–DE000` (default `C8000`), IRQ `2/3/4/5/7/10/11/15`, modes
   WD-CPX/WD-WDP/NE2000/NE1000. Driver checksums the MAC. ETS
   `NET WHO/ECHO` vs ZONE `HUNTER` vs Dactyl `DAC2` packet layouts are
   captured in `dumps_network.html`.
8. Software baseline: **DOS 6.22**, auto-loads game CDs if present, else
   diagnostics on the VGA control screen. Boot chain `mute → MSCDEX →
   vpcgo → run → runc → runtemp7.bat → game`; hardware described by
   `config.vpc` (§10); per-board diagnostics in ETS (§11).
9. Local archives beyond the websites: ROM dumps per board (`486/FORMAT1/
   FORMAT2/PIX1/TRACK1/TRACK2/VGA/VIDEO` + `devices.txt` PAL/GAL inventory,
   §9), full `SU-2000-cyberbase-Intercon-x` technical-manual OCR (9854
   lines), Simon's `VR 2000 Series Disc Image`, Faulty's `VR2000 HDD Dump`
   (ZONE game: `RUNFILES/MODELS/ROOMOBJ/ROOMS/TEXTURES/SOUNDS/VICS`, §12).

## 2. System overview: pod, backplane, board table

Provenance: SkullSpace unit bought very used from the Mall of America
(Minneapolis); arianchen.de's unit is a *different* physical machine, so
where the two disagree both facts are kept and marked.

### 2a. Pod (per-player platform hardware)
2-player system with 2 standing platforms; each platform has: visette HMD
(two displays + headphones), handheld 'joystick' controller, **emitter in
the handbar** for Polhemus 3D location of headset + joystick, **magnetic
card reader** (believed UK maker Ampy, long defunct — 'complex' signal with
encryption and/or per-read random + per-site 'site key', see §6/§13),
speaker + player buttons, the **'Format D' interconnection box (with
composite video out)** wiring all of the above, and a **12/5/-5V power
supply**. The main electronics box is a rackmount PC case under platform #1.

### 2b. Backplane slot order (14-slot ISA, viewed from the back going right)
"486" is an oversimplification — one mini-PC board + about a dozen custom
boards, 250W PC PSU, 500MB HD, two 4X(?) IDE CD drives, floppy:
1. graphics interface card (2-channel), 2 cables out to the pass-through card;
2. **2 graphics rendering cards, each with 2 fan-cooled DSPs(?)** + ribbon
   cable to (1) — consistent with PIX 1000's twin-MC88110 design (§4b), i.e.
   one dual-DSP card per player;
3. graphics pass-through card, 2 internal cables to the visette/sound/
   interface cards;
4. **2 Polhemus 3D I/O cards, each with a 3A0417 adapter box on a ~8in
   cable** — the 2-player unit carries *two* tracker cards (arianchen
   documents one InsideTrak Rev B in isolation, §7);
5. **2 visette/sound/interface cards ("Format C"?)** — one per player;
6. mini-PC card — **HMS-486** here (variant vs arianchen's ASC486 SBC, §3):
   4 RAM slots (max 64MB?), big+small IDE ports, 1 floppy, 1 parallel,
   2 serial, keyboard + mouse;
7. cheap network card — **10Base-2 generic** here (variant vs arianchen's
   COMPEX ENET16/V, §8; both are cheap 8390-class cards, matching the "any
   8390 + 16K works" note);
8. standard cheap VGA card for the control terminal;
9. **IDE interface card (extremely simple — 1 PAL + 2 74x chips)** with CD
   audio passthrough to RCAs — not in arianchen's board table below.

## 3. Host PC and system baseline (486 DOS PC)

`details_asc486.html`: ASC486 SBC Rev C. CPU i80486DX 33 MHz, ALI M1429
chipset, 4 MB SIMM (see DRAM table), 128 KB cache (see cache table).
(SkullSpace unit instead carries an HMS-486 mini-PC, §2b — either SBC works;
upgrades/quirks in §13.)

- Connectors: CN1 keyboard, CN2 power-LED/keylock, CN3 floppy, CN4 IDE LED,
  CN5 parallel, CN6 PC/104, CN7 keyboard port, CN9 serial1, CN10 serial2;
  JP1 speaker, JP2 reset, JP3 IDE, JP4 turbo switch, JP5 turbo LED.
- Battery JP11: ext 2&3 (default) / int 1&2. Clock JP15+JP46: double 1&2
  (default) / single 2&3. CMOS JP28: normal Open (default) / clear Closed.
- LPT JP31 IRQ: IRQ7 1&2 (default) / IRQ5 2&3. IDE JP32: enabled 1&2
  (default). LPT addr JP33: `378–37F` 1&2 (default) / `278–27F` 2&3.
  Floppy JP34: enabled 1&2 (default). Monitor JP38: color Closed (default).
  LPT mode JP39: unidirectional Closed (default). XT-IDE JP40: disabled 2&3
  (default). LPT enable JP43: enabled 1&2 (default).
- Serial JP41/JP42/JP44/JP45: `3F8+2F8`=1&2/1&2/1&2/1&2; `3F8+Dis`, `Dis+2F8`,
  `3E8+2E8`, `3E8+Dis`, `Dis+2E8`, `Dis+Dis` per table. Serial IRQ JP29/JP30:
  P1=IRQ4+P2=IRQ3 is 1&2/2&3; swapped 2&3/1&2.
- DRAM banks: 1 MB (4)×256K×9; 2 MB 256K×9+256K×9; 4 MB (4)×1M×9; 8 MB
  1M×9+1M×9; 16 MB (4)×4M×9; 20 MB 1M×9+4M×9; 32 MB 4M×9+4M×9;
  64 MB (4)×16M×9; 128 MB 16M×9+16M×9.
- Cache: 32 KB (4)×8K×8+16K×4 … up to 1 MB (128K×8 pairs + 64K×4); JP22/24/25/
  26/27 matrix in page (e.g. 128 KB = JP22 7&8+9&10, JP24 Open, JP25 2&3,
  JP26 1&2, JP27 2&3).
- CPU-type jumpers JP6/7/8/12/13/14 + JP16–21 matrix for 486SX/487SX/Cx486S/
  Cx486S2/486DX-DX2/OverDrive; speed JP23 (33 MHz = C/O/O/O) + int JP9/JP10.
- Watchdog JP35: Reset 1&2 / NMI 2&3 / disabled Open; timeout JP36/JP37:
  500 ms / 1 s / 2.5 s / 5 s.
- System baseline (SkullSpace): boots as a standard PC into **DOS 6.22**,
  then the Virtuality software; **auto-loads the game CDs if present**,
  otherwise diagnostics on the VGA control screen + AT keyboard. Storage:
  500MB HD + two 4X(?) IDE CDs + floppy (theirs; one note says 120MB HD —
  likely a replaced drive). ROM: `SU2000 ROMS\486\AMIBIOS_486DX_ISA_...` +
  U32 TMS27C512 (see §9).

## 4. Video chain (SVGA → FORMAT C → VID 1000 → HMD; PIX 1000 source)

### 4a. SVGA — `details_vga.html` (empty) + `su2000.html`
Hualon SVGA Rev 2.01, BIOS Rev 2.08, 256 KB RAM, "basic SVGA adapter". Any
substitute VGA works. ROM: `SU2000 ROMS\VGA\HMC86304_BIOS_V208.U7` (U7 M27256).

### 4b. PIX 1000 — `details_pix1000.html`
WI01REVB. 2× Motorola **MC88110** @ **40.0000 MHz OSC**; VRAM 4 MB
(16× TC528257SZ 256K×8); DRAM 8 MB (16× TC514400AZ 1M×4). **Each game ships
independent firmware for both CPUs** (hence per-game PIX ROMs).
J9 I/O select (`:` = open?, `|` = closed? as printed):
`:::::||`=3E0, `::|::||`=360, `::|:|||`=340, `::||:||`=320, `::|||||`=300,
`:|:::||`=2E0, `:|:|:||`=2A0, `:|:||::`=290, `:|:||:|:`=298, `:|:|||:`=288,
`:|:||||`=280. ETS observation: `Read 1 byte from 0300 (PIX1) - CF` after
every broadcast block. ROMs: `SU2000 ROMS\PIX1\WI01P*.bin` (U6/U26/U44/45/46/
48/49/50/53/54/56/58/67/70/72/73/74/75/79/80/83/92).

### 4c. VID 1000 — `details_vid1000.html`
REV ?. **27.0000 MHz OSC**, 8× AM7203A 2K×9 FIFOs, 5× IDT7132 2K×8 SRAMs,
"a sh!tload of 74'574s". JP5: `||:|::`=IO 340, `||::|:`=IO 2C0,
`||:::|`=IO 1C0. 9-pin output: 1 R, 2 G, 3 B, 4 SYNC (composite sync),
5 unknown, 6–9 GND. ROMs: `SU2000 ROMS\VIDEO\W102P*.bin` (U5/6/13/14/22/23/
31/32/49/51/52/72/74/82/85/86/88).

### 4d. Broadcast/OSD protocol — `su2000.html` (ETS logs)
2-byte writes to **port `0x320` (BCST)**, big-endian 16-bit words:
- `001F` + `0000,0001,0000,0000` — maybe clear screen?
- `001C` + `0000,0001,0000,0000,02BE`×702 (`0x2BE`=702), `0240` (`0x240`=576)
  — maybe open screen? (702×576 field noted)
- `0022` + `0000,0001` (channel 1 only), `0016,0000,00C0`, colors
  `0000,FFFF` (yellow #FFFF00), `00FF,FF54` (cyan #54FFFF); positions are
  value-minus-offset: `0029`=41−31=**x10**, `0030`=48−45=**y3**,
  `011B`=283−31=**x252**, `012F`=303−31=**x272**, `0200`=512−45=**y467**;
   lengths `000C`=12 "ETS 01.30.05", `0011`=17 "PONI GILBRAEIS", `0003`=3 "SEC".
- The same `broadcastFIFO 0x320` appears in `config.vpc` (§10); a second unit
  taps RGBS-level video at FORMAT C outputs for external monitors (§13).
- **Live confirmation 2026-10-12** (log-only BCST trap, words decoded little-endian
  as x86 `OUT AX` puts the low byte first; all 373 captured words parse with
  zero leftovers): ETS 02.03.08 prints exactly this grammar — `0022 0000 0001
  0016 1200 00C0 <col1> <col2> 0000 <x> <y> <len> <text>`, one `PIX1 0300`
  byte-read (answered `0xCF`) after every block. Observed boot screen in order:
  `ETS 02.03.08`, `OPENING LIBRARIES`, `Basic mode   ` (13 chars, padded),
  `SU2000`, `ESC`, `Exit`, `SPACE`, `Visette backlights`, then per library
  `MISC library` / `v00.01.07` / `Opened`, `EXP  library` / `v01.02.25` /
  `Opened`, `PIX  library` / `v01.05.65` / `Opened` (twice),
  `TRK  library` — then the TRK open (`W` → sign-on) with no further BCST,
  i.e. the TRK version line is skipped when the card gives nothing past the
  sign-on. (Library names carry a double space on the wire: `EXP  library`,
  `PIX  library`, `TRK  library`.) Observed PIX init writes first
  (`0300/0360 = 00/10/00…`, then `30/20` pairs, then `22/32`, then `23/33`
  pairs, all from `0160:ce4e`) plus `VID 0340 = 0x27`.

## 5. FORMAT C (audio + control + video-mix)

`details_format-c.html`: Rev C & Rev D (both in hand). Three functions:
(1) **Ensoniq Soundscape S-2000** (author unsure S-1000 vs S-2000),
MITSUMI CD-ROM IF, 4 MB SIMM sample RAM, 128 kbit DRAM;
(2) **FORMAT_C/D control IF**: N80C198 ROMless MCS-96 MCU + 2K×8 SRAM +
**32 KB ROM WFC062**; (3) **twin RGBS→composite converters**.
Oscillators **44.33619 / 14.31818 / 10.00000 MHz**.
RGB inputs PL5 (#1) / PL3 (#2), Datamate L-Tek (cable M80-8801098, card
M80-8511042). Rev C hardwired monoscopic; Rev D jumpers 2–3 bridge inputs
to mono.

- JP1 (Soundscape IO): `::`=350, `:|`=330, `|:`=340, `||`=320.
- JP5 (Soundscape IRQ): `|:::`=12, `:|::`=15, `::|:`=10, `:::|`=11
  (page notes techdoc says leave unjumpered; conflicts with Ensoniq driver
  IRQ table).
- JP3 (FORMAT_C MEM/IO, PLD revs WFC067A all-Rev-C+early-D / WFC067B
  later-D / one WFC067D seen → WFC067C probably exists):
  MEM WFC067A: D0000–D07FF `::|::---`, D0800–D0FFF `|:|::---`,
  D1000–D17FF `:||::---`, D1800–D1FFF `|||::---`, D8000–D87FF `:::|:---`,
  D8800–D8FFF `|::|:---`, D9000–D97FF `:|:|:---`, D9800–D9FFF `||:|:---`,
  E0000–E07FF `::||:---`, rest = not-found/boot-error (VGA ROM at
  C8000–CBFFF collides on author's test board).
  MEM WFC067B: CC000–CC7FF `::|::`, CC800–CCFFF `|:|::`, CD000–CD7FF `:||::`,
  CD800–CDFFF `|||::`, D0000–D07FF `:::|:`, D0800–D0FFF `|::|:`,
  D1000–D17FF `:|:|:`, D1800–D1FFF `||:|:`, E0000–E07FF `::||:`,
  E0800–E0FFF `|:||:`, rest = not-found/boot-error.
  IO: 210 `-----:::`, 218 `-----|::`, 260 `-----:|:`, 268 `-----||:`,
  298 `-----::|` and `-----|:|`, 2C0 `-----:||`, 2C8 `-----|||`.
- 2 KB window map (offset from window base): 0000 version (`0x21`=2.10 /
  `0x30`=3.00; stickers 2.12/3.00); 0001 `0x00`; 0002–0005 packetnum
  to/from format_d; 0006 status (`0x82`, else ETS "FORMAT-C NOT FOUND");
  0007 sync (`00` offline / `A5/5A` toggling online); 0008/0009 brightness
  L/R (default `0xFC`); 000A–000D joy1x/joy1y/joy2x/joy2y (`00–FF`,
  `0x7F` center); 000E–0011 glove1–4 (`00` = unused/SU?); 0012 config
  (overlaps buttons 5–12); 0013 switch (`00` none / `01` left-front /
  `02` left-top / `10` right/cs-front / `20` right/cs-top); 0014 console
  (`00` / `10` credit / `20` visette / `80` joystick security test);
  0015–0016 reserved; 0017 mic-peak (real value `0xB2`); 0018 security;
  0019 backlight; 001A–03FF `00`; 0400 cmd (`00–04`); 0401 sync `A5`;
  0402 format-d; 0403 collector; 0404 effects (`0x10`); 0405 lamp
  (low 4 bits lamps, `0x10` = loud siren); 0406 flash (needs 0405);
  0407 misc; 0408 backlight (via ETS); 0409 pixelshift (`05` default);
  0410–07FF `00`.
- Volume block (IO+0…7): regs 0–2 random/stable `00–FF`, 3 = `FF`,
  4 = `C0–E8` (high nibble C/E = video mode?), 5 = `FF` read but is volume
  control — two candidate codings: (a) write REG then VALUE, or
  (b) `1xxxxxxx`=SET REG / `0xxxxxxx`=SET VALUE; REG `x00`=9 L+R,
  `x01`=B Left, `x10`=D Right, `xxx10000`=FX, `10001`=AUX2, `10010`=CD,
  `10011`=AUX1, `10100`=MICNET, `10101`=MIC, `10110`=VISETTE,
  `10111`=EXTERNAL, `00001`=VISETTE_MASTER, `00010`=EXTERNAL_MASTER;
  VAL `x01`=EXTERNAL / `x00`=VISETTE, `xxx00000`=`00` mute … `11111`=`1F`
  full. Regs 6–7 = `FF`. Software side: `MUTE.EXE` zeroes these registers
  (§11); live matrix in `TESTVOLS` (§11).
- Audio jacks: 8-way mini-DIN 1 I-L/micnet IN-L, 2 I-R/IN-R, 3 O micnet out,
  4–5 unknown, 6–8 GND; 4-way 1 L, 2–3 GND, 4 R.
- Sample RAM: upgraded to 2× 4MB? (`TC514100AFT-60`) on a second unit —
  took, audible benefit unknown; **sticks must go in the front slot** or
  games crash on startup (§13).
- ROMs: `SU2000 ROMS\FORMAT1\WFC062_212.U62` vs `FORMAT2\WFC062_212.U62`;
  soldered PLDs WFC065A/066A/067A-B/071A/014A/072A (see §9).
- **WFC062 firmware disassembly 2026-10-12** (rizin `mcs96`, N80C198 code):
  both ROMs byte-identical (32 KB, AM27C256 vs M27C256B, same 2.12 image);
  only `0x2000–0x233F` (~1.3 KB) is code, the rest is `00`/`FF` fill.
  Interrupt vector table at `0x2000–0x2041` (default handler `0x233E`;
  distinct entries `0x230F` boot, `0x2338`, `0x228D`). Reset init at `0x2080`:
  SP=`0x44`, register-RAM + 2 KB SRAM `@0x8000` cleared, then seeds
  version `0x21`→`[0x8000]` (ISA `+0x0`, matches the 2.12 sticker),
  status `0x80`→`[0x8006]`, sync `A5`→`[0x8401]`+`[0x2A]`,
  pixelshift `05`→`[0x8409]`, effects `0x10`→`[0x8404]`, peripheral block
  `0x0800–0x0803` programmed, status `0x81`, a wait-on-`[0x2400]` (host
  command mailbox) delay loop, then status **`0x82`** (+ mirror `[0x1000]`).
  MCU↔ISA map confirmed: `[0x8000]`=version, `[0x8006]`=status,
  `[0x8400–0x8409]`=command block (`+0x00`/`+0x01` sync/`+0x04` effects/
  `+0x09` pixelshift all match the §5 map). Main loop: three subcalls plus
  a pet loop, a brightness servo (`+`/`-` in `[0x2B]`/`[0x2C]` driving
  `[0x0800]`/`[0x0801]`), and a command dispatcher on `[0x8400]` (cases
  0–4: volume/brightness paths). Consequences for emulation: the real card
  ramps status `0x80→0x81→0x82` (our skeleton answers `0x82` at once —
  boot-timing nuance, harmless so far) and owns the window bytes (status-area
  writes are MCU-side). String footprint is tiny (`Penny` + fragments).

## 6. FORMAT D + cabinet I/O (credit, joystick, card reader)

`details_format-d.html` is an empty stub (title only). `su2000.html`: "the
box *inside* the cabinet — didn't even take a look yet." Info ~0%, emu 0%.
Manual TOC reserves the "FORMAT D + Credit Module" chapter; the C↔D
diagnostic-cable procedure is in ETS (§11).

Second-unit facts (SkullSpace):
- The Format-D box is the **per-platform interconnection box (with composite
  video out)** wiring visette, joystick, emitter, card reader, speaker and
  buttons; one per platform.
- Joystick link is a **6-pin Mini-DIN from Format D to the joystick port on
  the System Polhemus board** — a broken white wire there caused single-axis
  drift + stutter (§13: check the cable before swapping boards).
- The magnetic card reader (Ampy, worn heads) emits a **'complex' signal
  (encryption and/or per-read random) plus a per-site 'site key'**; a 3-sec
  press of its 'data' button erases the key (unit then rejects that site's
  cards). Free-play angle: compatible-head swap, MCU 'money present' signal,
  or patching the DOS software to always report paid (§13).

  `+0x1` and data `+0x0` as WORDs (`in ax,dx`, helpers ~`0x1CCE46`/`0x1D913F`,

  (counter >= limit); buf[counter]=data_word(); repeat`) makes status bit 0

  the emulator mirrors both (dry status `0xFE`, dry reads floating-bus).

  `S` status record (`28 words expected`, `Firmware version`), then sensor

  `TRACK2\VER_151_01_U16/U17` (AM27C1024/M27C1024); soldered TIBPAL16L8
  U37/U40 undumpable.
- **TRACK firmware structure 2026-10-12** (no C31 disassembler available:
  rizin `tms320` covers C54x/C55x/C64x only, so code is not yet decoded;
  recipe for later: MAME `tms32031` core/disassembler + TI SPRU031/SPRU032).
  Each chip is one 16-bit half of 32-bit DSP words (U16 = low half: holds
  UTF-16LE data + code low halves; U17 = high half, zero across data areas)
  → 256 KB 32-bit image. Used areas only `0x0000–0x2FFF` (vectors/boot) and
  `0xC000–0x176FF` (~22 KB main firmware); `0x3000–0xBFFF` and
  `0x18000–0x3FFFF` are empty. Head words `000000D0 00022834 0002285C`
  (boot table/vectors, placement needs the board memory map — PLDs
  undumpable). Version block at 32-bit offset `0x297C`: `0123456789ABCDEF`,

  (the sign-on substring the TRK lib matches). 151.01-vs-151.03 diff is
  diffuse: 57 of 256 1 KB blocks differ across all used areas (near-total
  rework between versions, not just the version string).

## 13. Second-unit field notes: repairs, upgrades, projects

Source: SkullSpace wiki (unit bought very used from Mall of America;
page archived 2014; prices/plans are 1995–2014 era). Failure modes first —
they are the cheapest things to check on real hardware or in emulation.

- Joystick drifting on one axis + stutter: **broken white wire in the 6-pin
  Mini-DIN from Format D to the joystick port on the System Polhemus board**
  (found only after swapping joystick, transmitter, Format D and Format C —
  check the cable first).
- One player display all black after cleaning: **graphics→Format C cable
  inserted backwards + loose ribbon on the graphics card** (cable orientation
  is a first suspect — same class of fault as the VFX-1 VESA-cable warning
  in `VFX1.md` §2).
- Games crash on startup after sound-card RAM upgrade: **SIMM was put in the
  back slot, must be in the front slot** (slot order matters on FORMAT C).
- Card reader dead/flaky: read head worn; reader emits a **'complex' signal
  (encryption and/or per-read random number) + per-site 'site key'** — a
  3-second press of the reader's 'data' button **erases the stored site key**
  (unit then rejects all cards of that site); recovery by skimming a good
  card's site key and re-programming the reader. Replacement avenues noted:
  compatible head swap, MCU-generated 'money present' signal, or **patching
  the DOS software to always report paid**.
- Upgrades: PC RAM 4MB → 16MB (`RA72P16MBEDO` 16MB sticks, only half — one
  side — usable); tried `128M8` (`HY5117404BJ-60` chips): 4 sticks = no
  boot, 3 sticks = 64MB detected; left at 2 sticks = 64MB. FORMAT C sample
  RAM to 2× 4MB? (`TC514100AFT-60`) — took, audible benefit unknown. HD
  500MB → 2GB CompactFlash planned (**DOS 6.22 = FAT16 = 2GB per partition**,
  so CD images on HD need multiple partitions). CD 2× 4X(?) IDE → hoped
  newer drives speed loads; alternative **DOS CD emulator (0cd / FakeCD /
  CDemu2)** to run games off HD. Their unit: system on 120MB HD per one note
  (500MB in theirs, likely replaced), games on standard burned CDs; backed
  up the HD + 3 games (Dactyl Nightmare, Zone Hunter, Missile Command).
  On-board programmable ICs were *not* backed up; MAME assistance offered.
  CPU overclock planned, not done.
- Projects: tap **Format C board outputs for PAL/RGBS converter cables**
  driving two 25" RGBS monitors showing each player's view; install
  additional legit software packages; **FREE PLAY by hijacking card readers
  or patching admin/game software**.
