# EF2000 (DID) — VFX1 / CyberMaxx Headset Support Infodump

Source binary: `D:\Emu\DOS\C\EF20003DFX\_ef2000.exe` (**2,569,210 bytes = `0x2733FA`**, modified 1997-05-16), a 32-bit LE DOS4GW executable (arch x86, bits 32). Launcher: `ef2000.exe` (16,144 bytes, 1997-04-17). Supporting tools: `CONFIG.EXE`, `DIAGNOST.EXE`, `SETSOUND.EXE`. Scope: the VFX1 Headgear + CyberMaxx/i-glasses headset tracking code inside the game binary itself. Nothing below comes from emulator source — only strings + rizin disassembly of the DOS binary.

EF2000 is by ImageSpace/DID (Digital Image Design). It is one of the confirmed VFX1-capable titles — the game probes the VIP card directly and also supports a serial CyberMaxx/i-glasses tracker on a COM port.

## 1. The 30-second version

`_ef2000.exe` contains **two headset paths**:

1. **VFX1 (VIP card)**: a detection routine at `0x000ebfe0` scans candidate VIP base ports, calls a hardware-probe helper at `0x106c4`, and validates a state block at `[0x52b2d0]`–`[0x52b2ec]`. On failure it prints `Cannot find VFX1 headset! - rerun config` via the print routine at `dword [0x18b85c]`. The VFX1 error path lives at `0x000fb529`–`0x000fb538`.
2. **CyberMaxx / i-glasses! (serial)**: a serial-port tracker at `0x000ec0e0` opens a COM port, sends the cooked-mode command string `!M1,P,B\r` (stored at `0x00170dbc`), reads the response, and tracks state at `[0x52b310]`–`[0x52b364]`. On failure it prints `Cannot find Cybermax headset on com port %d!\n` (stored at `0x00172738`).

The README.TXT mentions **only 3Dfx stereo** (GLIDE/SST1) — no VFX1 documentation exists in the shipped text files. CONFIG.EXE and DIAGNOST.EXE contain no VFX1 strings either, so all VFX1/CyberMaxx logic is compiled into `_ef2000.exe`.

## 4. VFX1 detection (`0x000ebfe0`)

```
0x000ebfe0: push ebx/ecx/edx/esi/edi           ; save regs
0x000ebfe5: mov ebx, 0x60                       ; base-port scan start
0x000ebfea: mov ecx, 0x6000                     ; loop counter
0x000ebfef: mov eax, 0x33                       ; probe function code
...
0x000ec01b: call 0x106c4                        ; hardware probe helper
0x000ec020: mov eax, [0x52b2ec]                 ; read probe result
0x000ec025: or di, 0x7f00
0x000ec02a: and eax, 0xffff
0x000ec02f: cmp eax, edi
0x000ec031: jnz 0xec03c                         ; mismatch -> try next base
0x000ec033: mov eax, esi
0x000ec035: and eax, 0xff00
0x000ec04a: ... (fallthrough: VFX1 found)
0x000ec048: xor eax, eax                        ; not found -> return 0
```

The scan increments `ebx` (base) and `ecx` by `0x100` per iteration, looping while `ebx <= 0x70`, calling `0x106c4` (a hardware I/O probe that reads/writes state block `0x52b2d0`–`0x52b2ec`) and comparing results. On match, VFX1 is deemed present.

State block (VFX1): `[0x52b2d0]`, `[0x52b2e0]`, `[0x52b2e4]`, `[0x52b2e8]`, `[0x52b2ec]` — read/written by the probe and by the tracking path.

## 5. VFX1 error path (`0x000fb529`–`0x000fb541`)

```
0x000fb529: call 0xebfe0            ; VFX1 detect (RELOC TARGET 32)
0x000fb52e: test eax, eax
0x000fb531: jnz 0xfb57e             ; skip error if VFX1 found
0x000fb533: push str.Cannot_find_VFX1_headset ; 0x1726d8
0x000fb538: call dword [0x18b85c]   ; print/error routine (RELOC 32)
0x000fb53e: add esp, 4
0x000fb541: jmp 0xfb57e
```

If detection returns 0, the game aborts VFX1 mode with the `Cannot find VFX1 headset! - rerun config` message. This matches the user-visible behavior: running EF2000 in VFX1 mode without a configured/installed VIP card produces this error and falls back to non-VFX1 rendering.

## 6. CyberMaxx / i-glasses! serial tracker (`0x000ec0e0`)

```
0x000ec0e0: push ebx/ecx/edx
0x000ec0e3: mov eax, 1              ; serial open flag
0x000ec0e8: xor edx, edx
0x000ec0ea: mov ebx, 0x4b00         ; COM port / baud config
0x000ec0ef: mov [0x52b310], edx
0x000ec0f5: call 0x11b7c8           ; serial open/init (RELOC TARGET)
0x000ec0fa: mov edx, 0x52b365
0x000ec0ff: mov ecx, eax
0x000ec101: mov eax, 0x52b310
0x000ec106: call 0x11bbe4           ; serial send (RELOC TARGET)
0x000ec10b: mov byte [0x52b364], al ; store result
0x000ec110: test al, al
0x000ec112: jz 0xec124              ; if open failed, goto failure path
0x000ec114: mov eax, 0x52b310
0x000ec119: call 0x11bc1c           ; serial read (RELOC TARGET)
...
0x000ec124: mov eax, 2              ; failure return code
...
0x000ec129: mov edx, str.!M1_P_B    ; 0x170dbc ; "!M1,P,B\r"
0x000ec12e: call 0x11b7c8           ; serial open/init again
0x000ec133: mov ebx, eax
0x000ec135: mov eax, 0x52b310
0x000ec13a: call 0x11ba0c           ; serial write (RELOC TARGET)
0x000ec13f: mov byte [0x52b364], al
0x000ec144: test al, al
0x000ec146: jz 0xec158              ; failure path
0x000ec148: mov eax, 0x52b310
0x000ec14d: call 0x11bc1c           ; serial read response
...
0x000ec158: mov eax, 1              ; success return code
```

State block (CyberMaxx/serial): `[0x52b310]`–`[0x52b364]` — holds the open port handle, baud/port config, and last read result.

The command `!M1,P,B\r` is the **i-glasses! / CyberMaxx cooked-mode binary packet request** (mode 1 = cooked/polled, P = position, B = binary), matching the protocol documented in `IGLASSES.md` and the VFX1 SDK. The game opens the COM port, sends `!M1,P,B\r`, reads the 12-byte cooked response, and extracts yaw/pitch/roll.

On failure at either stage, the game prints `Cannot find Cybermax headset on com port %d!\n`.
