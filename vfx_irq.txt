VIP Card IRQ Detection Mechanism
================================

Based on analysis of D:\Emu\DOS\C\VRDRV\vfx1sdk and related files.

KEY REGISTERS (from VFX1.H):
- VIP_IRQCFG at offset 0xA  -- IRQ Configuration register (KEY for IRQ detection)
- VIP_AIR at 0x0            -- Access Bus Internal Register
- VIP_CSR at 0x1            -- Control/Status Register
- VIP_HWID at 0xC           -- Hardware ID
- VIP_HWVLOW at 0xD         -- Hardware Version Low
- VIP_HWVHI at 0xE          -- Hardware Version High
- VIP_CFGSTATUS at 0xF      -- Configuration Status

CONTROL BITS (from VFX1.H):
- PC2ABREQ 0x01  -- PC --> A-bus Request
- PC2ABACK 0x02  -- A-bus Acknowledge
- AB2PCREQ 0x04  -- A-bus --> PC Request
- AB2PCACK 0x08  -- A-bus --> PC Acknowledge
- PC2ABAV1 0x10  -- A-bus Valid 1
- AB2PCEMPTY 0x20 -- A-bus to PC Empty
- DSPINTR 0x40   -- DSP Interrupt
- PCIEN 0x80     -- PCI Enable

DETECTION PROCESS:
1. Read VIP_IRQCFG register (offset 0xA) -- Gets the VIP card's assigned IRQ
2. Test the IRQ -- Using VIPIRQStatus/VIPTestInterrupt from SETVFX1.EXE,
   test by attempting ACCESS.bus communication
3. ACCESS.bus Protocol -- Communication through ports ABUS_CONTROL (0x8)
   and ABUS_DATA (0x9) with control bits above
4. Validate -- If ACCESS.bus transactions succeed at detected IRQ, card is
   properly configured

AUTOEXEC.BAT CONFIGURATION:
  SET VIPPORT=2x0 Iy
  Where x = base port (6, 8, A, C)
  And y = IRQ (5, 7, 10, 11, 12, 15)

CONFLICT DETECTION:
  SETVFX1 checks for IRQ/baseport conflicts with other devices (especially
  sound cards), verifying VIP card and sound card use different IRQ and Port.
  "+S" option can force software palette snooping if needed.

CORE MECHANISM:
  The VIP card stores its configured IRQ in the VIP_IRQCFG register at
  offset 0xA. The driver reads this value then tests it via ACCESS.bus
  communication to confirm the IRQ is working correctly and not conflicting
  with other hardware.
